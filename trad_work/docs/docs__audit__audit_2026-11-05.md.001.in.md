# Audit complet du 05/11/2026 : le portage contre le jeu mobile (ce qui manque, ce qui bug)

Demande de Sylfried (05/11/2026, 01 h 07, point 9 : D-240) : « relancer un audit complet, clore les sujets et issues concernés, en créer de nouveaux si de nouveaux problèmes sont trouvés […] je ne te demande pas de modifier quoi que ce soit, juste de faire l'état général du projet pour le comparer à la version mobile pour savoir ce qui manque et ce qui bug ».

**Méthode.** Huit relecteurs indépendants, en lecture seule, un par domaine (moteur et fichiers, couche Unity et scènes, services et scénario, interface, cartes, sprites, combat, son), sur `main` = `becda5c` (après les 291 pull requests). Chacun a inventorié le jeu d'origine de son domaine (code IL2CPP, moteur natif, données des APK), rejoué le portage (moteur réel sans fenêtre, visionneuse en capture sous Xvfb, tests du dépôt sur une copie) et rendu un verdict sur **chaque issue ouverte** de son domaine. **Aucune ligne du code n'a été modifiée** ; seuls des documents (ce fichier et ses liens) et les issues GitHub ont bougé. Toutes les preuves sont des essais sur Linux : **rien n'est prouvé pour Windows, le GPU ou l'oreille**, et il n'existe aucune capture du jeu mobile. Les marques sont celles du reste du dossier : **Établi / Supposé / Non vérifié**.

**Issues.** 123 ouvertes avant l'audit ; **11 fermées** (recherches terminées et fonctions supprimées par ta décision D-226) ; **17 créées** (#292 à #308) ; **1 mise à jour de priorité** (#249 passe en haute) ; 14 commentées ; une étiquette `test-windows` ajoutée (#235). Les issues dont tu avais demandé le test sur Windows (commentaire « reste ouverte jusqu'à ta validation ») **restent ouvertes**, même quand l'audit confirme le correctif : c'est toi qui les fermes.

**Rectification du 05/11/2026, 10 h (#310)** : le paragraphe suivant disait « aucune régression » et c'était **faux pour le renommage D-239** : sous Windows le jeu plantait au premier dessin d'un menu (`TypeError: 'bool' object is not callable`). La méthode `_cachee` avait été renommée `_hidden`, nom que la fenêtre Windows de pyglet (`Win32Window._hidden = False`) possède déjà. Mon audit tournait sous Linux, où cet attribut n'existe pas : l'erreur était invisible, et je n'avais cherché que les collisions entre noms du projet, pas celles avec les classes de pyglet. **Corrigé en #310** (méthode devenue `_menu_hidden`, clic de souris pendant les logos ignoré sans lire `self.engine`, test `tests/test_window_name_collisions.py` qui lit le code de pyglet pour toutes les plateformes). Autres collisions cherchées ensuite (classes héritant de bibliothèques, noms masquant un module ou un builtin, noms écrits dans des chaînes, attributs posés sur des objets de pyglet ou de numpy) : aucune autre trouvée. Reste **non vérifié** : le jeu sous Windows après la correction.

**Régressions des PR #196 à #291** (avant cette rectification) : aucune régression de comportement trouvée dans les sept autres domaines (caméra exacte du jeu, rotation par les boutons du jeu, Paramètres sans pause, notifications limitées aux sauvegardes, historique, version anglaise, dossiers renommés, sauvegardes dans un seul dossier, tous vérifiés par essai) ; seule la correction du ciel d'`ev09` (#250) est incomplète, et le renommage D-239 a laissé des dégâts en commentaires et en documents (#296).
