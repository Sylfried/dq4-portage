## Avant la partie : logos, titre, menu de départ, nom, licence (01/11/2026, #39)
Sources : `libil2cpp.so` relu par instruction (RVA donnés) et traces du moteur sous Unicorn. **Établi** = lu dans le code ou observé dans une trace ; **Supposé** = déduit. Réalisation : `dq4_pc/avant_partie.py` (logos, « Touchez l'écran », copyright, Licence), `dq4_pc/saisie_nom.py` (clavier du nom), intégration dans `window.py` (`_maj_titre`, `_dessiner_titre`, `_maj_saisie_nom`, `_maj_licence`…) et `engine.py`.

- **Ce qu'Unity fait avant le moteur** (établi) : `Boot.Start` (langue, caméra orthographique de taille `225 / aspect`) → `Boot.Logo` (0xCC5618) → scène `dq4sp` → `MainLoop.Start` (initialisations, écran noir) → le moteur pilote tout. Google Play Games, OBB, téléchargement, `ApplicationQuit` (dialogue « quitter » du Retour Android) : sans objet ou code mort sur PC. **Aucun écran de titre n'est dessiné par Unity** en dehors de `TapToStart` et du copyright : logo 3D, fond et musique viennent du moteur (paquets 0, 21, 31, 11, 10, 37).
- **Logos** (`Boot.Logo`) : quad de 450 x 450 unités centré (texture 720 x 720, shader `Custom/Picture`, fusion alpha). Ordre `warning`, `sqex`, `arte_logo720_240` ; **« warning » (avertissement pour mineurs) seulement en langue 0 (japonais)** : en français ne passent que SQUARE ENIX puis ArtePiazza. Pour chacun : entrée en fondu 1 s, maintien 3 s, sortie 1 s (secondes réelles, `Time.deltaTime`), donc 5 s par logo. Un toucher pendant l'entrée saute le maintien ; pendant le maintien, il lance la sortie. Textures extraites de `base.apk` (`sqex`, `arte_logo720_240`) dans `cache/ap_*.png`.
- **Séquence du moteur au titre** (trace) : partie 0xC (TownPart) charge la carte `ev/ev01/out/ev01` (paquets 0, 8, 21 x 3 : modèles 8900 / 8901 / 8905, 31, 11, 9, 10, 37), crée le **port 12, type 73** (`[12,1,1,73]`, puis `[1,0,0,0]` et `[8,1]`). Puis **plus rien** tant que le pad A n'est pas pressé. **1er appui A** : fondu sortant (`[4126]`), ~30 images plus tard message `[12,0,0]` (code 0 = `TapToStart.CountReset`) et fondu entrant. **2e appui A** : fondu sortant, BGM `[16392]`, puis **partie 0x3 (GameStartPart)** : le moteur ferme le port 12 et crée 12 (type 74, vide), 13 (type 53, menu), 14 (type 54, liste). Supposé : le 1er appui termine la phase d'attraction (démo de caméra) ; le rôle exact de cette phase n'est pas établi.
- **`TapToStart`** (type 73 ; `Make_TitleTouch` 0xCE4ED8, `Update` 0xD0C738) : quad « Touchez l'écran » de 223,04 x 41,48 unités, centre à 228 unités sous le centre de l'écran ; quad de copyright de 450 x 40 centré à 25 unités du bord bas. Clignotement par image rendue : alpha +0,025 / image (40 images), plein 20, descente 40, vide 20 ; **premier affichage après 720 images** tant que `CountReset` n'est pas reçu, qui le déclenche tout de suite et fixe le copyright à pleine opacité. Sans `CountReset`, le copyright monte après 690 images (+0,0625 / image), s'efface à 2508 puis ne revient plus. `TapToStart.Update` n'envoie rien au moteur ; l'entrée est le **pad A (0x10)**.
- **Menu de départ** (type 53, port 13, `Make_StartMenuSecond`) : Unity envoie à l'appui `envoyer_menu(13, 1, idBouton, 16)` (le pad ne fait rien ici). **Les identifiants sont ceux du tableau, pas les numéros d'items** : 0 Continuer votre aventure, 1 Reprendre une aventure interrompue, 2 Créer un nouveau journal, 3 Supprimer un journal, 4 (bouton sans libellé, usage non établi), 8 Sauv. cloud, 11 Licence, −1 Retour (pad B = 32). Placement (conception 450 x 800) : écran 7 (bas-centre), z = 272,5 / 215 / 157,5 / 100 pour les quatre premiers ; Licence en bas à gauche, cloud en bas au centre.
- **Cloud** : l'octet `g_isAmazon` du moteur (lib + 0x24f684) mis à 1 après `GameInit` supprime la case « Sauv. cloud » (l'original fait de même pour Amazon) ; la plaque est aussi masquée côté visionneuse. Sans cela, un appui sur le bouton 8 ferme les ports 12 à 14, ouvre un port de catégorie 4 (`NetConnection`) et **attend une réponse d'Unity qui n'existe pas sur PC : écran bloqué**.
- **Liste des journaux** (type 54, port 14) : Continuer = banques 0 à 2 (journaux manuels) ; Reprendre = banque 3 (suspension) ; l'auto = banque 4. Choisir `envoyer_menu(14, 1, i, 16)` ; le moteur répond par ses messages (`b0833000.mpt`, identifiants globaux) et par le Oui / Non (type 1, port dynamique 2, curseur piloté par le moteur). Machine à états `MaterielMenu_LOAD` : 0 racine, 1 / 2 préparation Reprendre / Auto, 4 liste, 6 saisie du nom, 7 `makeDiary`, 8 suppression (`killbank` écrit `DLED`), 9 `loadbank` puis 0xb fin ; 0xe à 0x10 Licence.
- **Cadre de la liste (type 54)** : le moteur envoie le code 3 (`[12,3,c]`) : c = 0 (cadre 219, 316 de haut, onglet de titre de 241,5 de large : liste de trois journaux avec titre), 1 (220, 262, sans onglet : titre vide) ou 2 (221, 260, onglet de 301,5 : une seule ligne, « Reprendre » et « Auto »). Le code d'origine (0xD0A604) ne déplace que les boutons ; le texte du titre étant posé pour le cadre 219, la visionneuse le suit sur l'onglet (`Fenetre._titre_onglet` : abaissé de la hauteur perdue, décalé de la moitié de la largeur gagnée) : sans cela il flottait au-dessus de l'onglet dans la liste « Reprendre ». **Choix du portage**, pas lu dans le code.
- **Fichiers de sauvegarde** (inchangé, rappel) : `data1..3.dat` journaux, `data4.dat` suspension, `data5.dat` auto (15 360 octets, chiffrés par `Cryption::Filter`), `data9.dat` (512 octets, banque la plus récente, « DWEN » = aucune). Sans fichier, le moteur crée les six fichiers : le dossier d'écriture doit être inscriptible. La visionneuse lit dans `--saves-lecture` (la sauvegarde la plus récente de `jeux\DQ4\saves` par défaut) et écrit dans `--saves-ecriture` (`dq4_pc\sauvegardes`) : les sauvegardes de Sylfried ne sont jamais modifiées.
- **Licence** (type 80, port 15 ; `Make_License` 0xCF7228) : le moteur lance un fondu sortant `[20510]` (bit 14 : l'interface reste visible) puis, 30 images plus tard, crée le port 15 type 80. Texte : `Menu/License_list_A` (variante Android, 23 626 octets, 488 lignes, CRLF, titres `<color=orange>…`) lu dans `datapack.unity3d`. Fenêtre à défilement (`LicenseNobu` : barre de défilement glissée au pointeur) et bouton « Privacy Policy » (`LicensePolicy`) qui ouvre `https://square-enix-games.com/en_US/documents/privacy` (langue ≠ 0 ; `https://www.jp.square-enix.com/privacy/` en japonais). Retour : `envoyer_menu(15, 1, -1, 32)` ; le moteur répond par le fondu entrant `[16414]` et ferme le port 15. **Garde-fou du fondu** : `Etat.tick_fondu` ramène l'écran au ciel après 180 images de noir ; tant que la Licence est ouverte, la visionneuse remet `fondu['noir']` à 0 chaque image.
- **Saisie du nom** (type 55, port 15, `StartNameEntry`) : le moteur envoie `[12,0,8]` (code 0 = `SetLanguage`, 8 caractères au plus) et `[12,1,1]` (affiche clavier et boutons du sexe), `[12,1,0]` pour masquer. L'original (`InputName`) : grille de 5 colonnes x 7 lignes (35 caractères par page, pas de 69 x 82 unités, boutons de 30), pages alphabet (minuscules / majuscules), accents (`C_AA`, minuscules / majuscules), boutons « Alphabet », « à À », « Maj. », « Suppr. », « OK ». **OK** : le message `[2, n]` (n = nombre d'octets UTF-8) **puis** les octets empaquetés petit-boutiste en shorts, **en deux envois séparés à la MÊME image** (un seul message combiné fait planter le moteur : `memcpy` sur une adresse non mappée). **Annulation** : `[1, -1, 32]` (et non `[1, 32, 0]`, qui ne fait que déplacer le curseur). Choix du sexe : `[1, 0|1, 16]` sur le même port.
- **Drapeau de fermeture des ports** (`engine.py`) : les messages d'arrêt du moteur peuvent remettre `act` à vrai après `[N,2]` ; `f['ferme']` (levé à la fermeture, baissé à la création) dit si le port est vraiment fermé. Les écrans du nom et de la Licence s'appuient dessus.
- **Échap au menu de départ** : partie `PARTIE_DEPART` (0x3) → `_echap_retour` renvoie vrai quand le clavier du nom, la Licence ou un menu est ouvert (Échap = Annuler, comme le bouton Retour / pad B) ; à la racine du menu, le retour du moteur ouvre sa boîte « En êtes-vous sûr ? » (Oui / Non). Le menu Pause (réglages, touches) n'existe pas avant la partie.
- **Création d'un journal** (trace, établi côté moteur) : liste vide → saisie du nom → sexe → `makeDiary` (0x194a50) → fondu `[4126]` → prologue en `mlb1a`. Vérifié de bout en bout sous Unicorn jusqu'à l'arrivée en `mlb1a`.
- **Inconnues** (ne pas inventer) : disposition d'origine du clavier du nom (origine de la grille, boutons de fonction, `SetMode` 0xCE11BC) ; rôle du bouton 4 du menu racine ; rôle de la 1re phase du titre ; cadence réelle d'Unity (30 Hz supposé) ; positions exactes de la fenêtre Licence (`CreateBuildVariableWindow`) ; réponses attendues par `NetConnection` ; numérotation du pivot de `MeshMaker.Build` (4 = centre, déduit) ; liens id de modèle 8900 / 8901 / 8905 → objets Unity du titre ; sens des paquets BGM 16384 / 16392 ; effets de `g_isAmazon` au-delà de la case cloud ; différence entre SAVETYPE 1 et 2.

## Sauvegardes : lecture du catalogue, export / import (01/11/2026, #40)
**Établi** (code désassemblé + traces) : `profile::SaveLoad::getCatalogView()` (0x19a9ec) relit les cinq banques (`memoryload`, somme de contrôle) et remplit `catalogView_` (5 x 0x60 octets à 0x259b94) ; `getCatalogStatus()` (0x19af88) et `getCatalogRecent()` (0x19b050) en dérivent masque de statut et banque la plus récente. Le moteur ouvre les fichiers `data1..5.dat` et `data9.dat` **à la création du menu de départ** (image ~366 d'un lancement normal, deux passages) et **pas à l'ouverture des listes** : les listes (Continuer, Reprendre…) lisent le catalogue en mémoire.

- **Après un import**, la visionneuse rappelle `getCatalogView` puis `getCatalogRecent` (`Moteur.relire_journaux`, appels directs au moteur entre deux images, comme `charger_sauvegarde`) : les listes montrent aussitôt les nouveaux fichiers (testé : `data1` et `data2` échangés, « 1: Sofia / 2: Solo » sans relancer).
- **Non relu** : l'état des boutons du menu racine (cellules 0 et 3 grisées sans journal, cellule 1 selon le bit 3, cellule 4 « Sauvegarde automatique » seulement si le bit 4 est à 1) est posé par `MaterielMenu_LOAD` (`menuSetup` 0x193ce8, `updateActiveDiary` 0x193f4c ne règle que le curseur par défaut) à la création ; ni `menuSetup` ni la reconstruction du menu n'ont été tentés (risque de ports en double). La visionneuse compare `etat_boutons_depart(statut avant)` et `(statut après)` et demande de relancer le jeu si le résultat change.
- **Format de l'export** : .zip à plat, `data1.dat`…`data5.dat`, `data9.dat` (copie octet pour octet, les fichiers du jeu ne sont pas interprétés), `etats/etat_NN.dqs`. Import : noms reconnus par expression régulière (aussi dans des sous-dossiers d'un .zip) ; tailles contrôlées (journaux 0x3c00 = 15 360 octets, `data9.dat` 512). Les fichiers du dossier d'écriture remplacés sont copiés dans `avant_import_<date>/` avant l'écriture ; le dossier de lecture n'est jamais modifié.
- **`g_isAmazon`** reste à 1 : le moteur ne gère jamais la cellule 8 (réseau) ; l'appui sur la plaque « Sauvegardes » (envoyée comme bouton 8) est intercepté par la visionneuse avant d'atteindre le moteur (`_saisie_menu`, `on_mouse_release`).

## Caméra de la ville pilotée par le jeu, bruitage 300 des messages (01/11/2026, #40)
**TownCamera** (objet statique `_ZN10TownCamera11m_singletonE` ; établi par désassemblage de `execute`, `setCameraLock`, `setMoveTo`, `setTargetPlayer`, `setMoveTragetChara` et lecture mémoire) : +0x34 / +0x38 limites de rotation gauche / droite (négatif = interdit), **+0x3e verrou de la caméra** (0 = elle suit le joueur, 1 = menée par le jeu), +0x40 verrou de point de vue, +0x43 déplacement en cours, +0x48 mode de cible (0 aucun, 1 à 4 déplacements, 5 = un personnage, 6 = le joueur). Verrou posé par `setCameraLock(true)` (`cmd_map_event_camera::initialize`, `TownFallAction`, `TownActionRura`, `TownActionRuraFailed`, `TownPlayerAction::setup`), `setMoveTo`, `setTargetPlayer(true)`, `setMoveTragetChara` ; levé par `__cmd_camera_move_to_player::isEnd` et `setCameraLock(false)`. Prologue (slot 2, `mlb1a`) : `(1, 5, 0, 0)` des images 12 à ~368 (cible à 23,2 unités du héros), puis `(0, 0, 0, 0)`. **`PlayerManager::setLock`** (0x1c63e4) tient un compteur : le bit 0x4 de `Global.Flag` vaut « joueur verrouillé » (aussi pendant les messages), ce n'est **pas** un indicateur de caméra pilotée.

**Bruitage 300 au début d'un message** : `ui_MsgBeginTalkSE` (octet lib + 0x252388) est armé par `PlayerManager::setLock(false)` (+0x5c, quand le compteur retombe à 0 ; appelants vus : `cmd_player_lock`, `TownFurnitureManager::execute+0x44`) et consommé par `ui_MsgLoop()+0x1b8` (0x157044), qui joue alors SE 300 ; `ui_MsgLoop` joue aussi le 300 à 0x157114 à chaque page. Jarre à message (sonde) : 319 (jarre brisée ; 320 tonneau, `TownFurnitureObject::openObject`), 326 (icône de l'objet, `TownRiseupIcon::execute`), ouverture du message, **300** (le « bip »). Autres : SE 304 à l'ouverture d'un Oui / Non (`CommonMenu_YESNO::menuSetup`), 305 vu une fois (cause non analysée). Côté Unity : `cmd_se_play` (0xD150A8) → `Sound.PlaySE` (0xD15128), sans condition ; Unity ne joue lui-même le 300 que pour les boutons de menu (`MenuPortItem.Update`, `TouchPad.internalUpdate`, `InputName.Update`).

## Prologue : titre de chapitre, coups d'épée, plans de fondu (01/11/2026, #40)
Résumé de l'enquête (le journal complet des paquets image par image n'est pas conservé dans le dépôt ; `DQ_PKTALL=<fichier>` et `DQ_UIDBG=1` le reproduisent). **Établi** = lu dans le code ou observé dans une trace ; **Supposé** = déduit.

- **Chronologie sur `mlb1a`** (nouveau journal ; images du moteur, transitions à vitesse 2) : fondu au noir de la création (1236) ; carte chargée (1253) ; **plan de fond** sorti en 1 image (`9 [20481]` = 0x5001 : fond noir immédiat) ; caméra dans le vide ; plan de devant noir puis **bandeau « Prologue »** (port 12, type 12, `Make_Chapter`) en entrée 60 images, maintenu, sortie 45 ; plan de fond rouvert en 45 images (`9 [16429]` = 0x402D) ; **cinq coups d'épée** (paquets 21 : modèles 5303 « traînée » et 5311 « éclat » sur les emplacements 0 / 1, bruitages 412 / 416 / 403) ; plan de fond sorti (`20483`), **travelling** de la caméra vers le héros (paquet 10 x 10, paquet 13 `[2048]`), plan de fond rouvert : la salle apparaît ; `cmd_key_wait_type_b` (attend un appui) puis « Eh bien alors, [nom] ? ».
- **Deux plans de fondu** (établi, `Fade.Start` CD0B7C) : indice 0 « FadeForMenu » (`Custom/FrontFade`, file Overlay), indice 1 « FadeForBG » (`Custom/BackFade`, file Background). Non reproduit : `SetFadePriority` (appelé par `MenuMessage.SetCanvasMesh`, pas déclenché ici).
- **Bandeau** (`Make_Chapter` 0xCE4404, code `b__0` 0xD0ABEC) : quad `MenuParts.CreateFromTexture("Menu/map/hyodai1", bFitWidth = true, haspect = 1)` (0xD02764) ; texture `hyodai1` 256 x 128 dans le `datapack` (cadre doré à fond bleu), **créée par code, absente de l'export de mise en page** : la visionneuse la pose (`ui_menu.py`, `Fenetre.__init__`, 450 x 225 : la hauteur 225 est **supposée** d'après le rapport 256 x 128) et l'extrait une fois (`avant_partie.RESSOURCES['ap_hyodai1.png']`, 3,7 s au premier lancement). - **Boîte violette** : `MenuPortSystem.internalUpdate` (0xD10A54) traite le port 0 puis les ports 1 à 31 ; `[N, 2]` met `s_ports[N] = null`, un message adressé à un port nul est abandonné. Le portage gardait la fenêtre fermée et lui appliquait les messages suivants de la même image (la fin de la liste des journaux : `[5, 0]`, `[6, …]`, `[4, …]`) : elle revivait une image en « fenêtre simple » violette. Vérifié image par image sur choix de la sauvegarde → nom, emplacement occupé → confirmation, sexe → création, Supprimer (confirmation, Oui, retour), Licence → titre.
