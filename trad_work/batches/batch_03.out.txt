Message font of the game: the one the engine uses to draw dialogues and battle messages in its text canvas (SDrawCTRL / TextCanvas), not the SE-GARRIR menu font.

The file (`assets/English.font` of the data pack, copied into the cache by `extract_message_font`) is read as is, with ALL its glyphs: a character that the patch or another game of the series (DQ5, DQ6) adds to the font
is therefore displayed without changing anything here. Format (found in `SFont::Load`, `FontHeader::GetGlyph`):
  - 28-byte header: "TNOF", then (at byte 24) the height of a glyph cell (24);
  - table of 65,536 entries of 4 bytes (UTF-16 code -> entry): high byte = glyph width (bits 0 to 6) and flag (bit 7), the other 24 bits = glyph position in the data;
  - data: for each glyph, `width_px x height_px` opacity bytes (0 to 255), row by row, compressed: a byte "1xxxxxxx" repeats the next byte `xxxxxxx` times, a byte "0xxxxxxx" is followed by `xxxxxxx` bytes
    as they are, a 0 byte ends the data.
Placement (`SDrawCTRL::PutChar` 0x1575a0 and `TextCanvas::PutChar` 0x152820 of libdq4core.so; checked pixel for pixel against the canvas of the real engine, tests/test_message_font.py): the write position advances by the
glyph width; a flagged glyph (V, W, t, v, w, y of the patch) is placed one pixel further left and advances two pixels less (kerning); the space advances by the engine's space width (6, `obj + 0x38`) and not by the
glyph width (5); the tab by `obj + 0x3c`; the wide space U+3000 by `obj + 0x3a`; line breaks (U+000A, U+000D) do nothing; "$" is not drawn for language 1 (English) and ";" is drawn
(as a space) only for language 2; a code absent from the font is drawn with the glyph of "@" (entry 0x40 of the table: `[FontHeader + 0x128]`). Each glyph REPLACES the pixels of its cell (there is no
blending); a gap between letters (`g_letterSpace`, 0 in game) is added to each advance.
Module without pyglet: only `line` (the texture of a line) needs it.
