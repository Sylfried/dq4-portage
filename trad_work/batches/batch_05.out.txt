All the port's folders and files, in one place (tidy-up of 2026-11-04, English names of 2026-11-05: D-239).

Everything that is yours (APKs, saves, caches, settings) is in ONE folder, `data\`, at the project root; it is never sent to GitHub (.gitignore):

    data\
      apk\                      the 3 French APKs (base.apk, split_config.arm64_v8a.apk, split_UnityDataAssetPack.apk)
      saves\                  ONE SINGLE folder (D-232): the exact content of the export .zip, to copy the phone's saves in one go
        data1.dat ... data5.dat, data9.dat   the game's adventure logs (read and written by the engine; the phone's are copied here)
        savestates\           the savestates (state_01.dqs ...)
        before_import_<date>\   safety copies made before each saves import
        before_tidy_<date>\     old `portage\` and `mobile\` folders tidied away as they were by the migration (see `migrate`): safe to delete once the saved game is verified
      cache\                    what the port computes from the APKs (maps, sprites, sounds, menus): safe to delete
      settings\               settings.json, history_favorites.json, history_messages.json
      logs\                   window_errors.log
      resume.json               the migration steps of the old layout already done (D-235)

Two environment variables, for tests and special installations (the old names DQ4_DONNEES and DQ4_JEUX still work):
  DQ4_DATA  : another location for the whole `data` folder.
  DQ4_GAMES : (old behavior) a "jeux\DQ4" folder containing `patched_apks` and `saves\<date>`; it replaces `data\apk`, and `saves\<date>` remains a READ-ONLY copy of saves (tests, special installations).

English names (D-239): the folders and files that earlier versions created in French (`donnees`, `sauvegardes`, `etats\etat_NN.dqs`, `reglages`, `journaux`, `avant_import_...`, `reprise.json`...) are RENAMED in place at first startup
(`english_names` in `resume.json`): a plain rename, without copying, overwriting or deleting anything; if a name already exists at the new location, the old file stays where it is and the rename is redone at the next startup.

`migrate()` also takes over the old layout (jeux\DQ4, dq4_pc\cache, dq4_pc\sauvegardes, dq4_pc\reglages.json ...): it COPIES (or, for the cache only, moves) to the new one,
without ever overwriting a file already present and without deleting anything. Each migration happens ONLY ONCE (D-235): `data\resume.json` records the steps done, so that what you delete in `data\`
(a `before_import_...` folder, a log, settings) is not copied back from the old folder at the next startup. A layout already in use (adventure logs, savestates, settings or cache in `data\`) counts as migration done.
